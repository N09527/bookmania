# WebDAV 同步格式（第 1 版）

Android（Kotlin）與 iOS（Swift）的同步程式都照這份規格實作。兩邊的單元測試讀寫同一批測試資料（`core/sync/src/test/resources/fixtures/sync/`），確定讀寫結果與合併結果相同。設計的理由見 [design.md](./design.md) 第 3 節。

## 1. 遠端結構

使用者設定一個 HTTPS 的 WebDAV 網址（例如 `https://example.com/dav/`），App 在它下面使用：

```
Bookmania/
  sync-v1/
    devices/
      <裝置 id>/
        device.json                 這台裝置的名稱與平台
        library.json                書櫃、分類、設定、各作品進度檔的索引
        progress/<作品鍵的 SHA-1>.json  一部作品的章節進度
        files.json                  這台裝置上傳過的書檔清單
    files/
      <作品資料夾>/<檔名>           書檔（本機來源），各裝置共用
      <作品資料夾>/<子資料夾>/<檔名> 圖片資料夾形式的章節
```

- 每台裝置只寫 `devices/<自己的 id>/` 底下的檔案，以及 `files/` 底下它上傳的書檔。
- 讀取時合併所有裝置的檔案。因為不會有兩台裝置寫同一個檔案，不需要伺服器的鎖定或條件寫入。

## 2. 識別碼

| 名稱 | 格式 |
|---|---|
| 裝置 id | 第一次開啟同步時產生的隨機 UUID，小寫、含連字號，存在本機 |
| 作品鍵 | `<來源 id 的十進位>:<作品網址>`。本機來源的 id 是 `0`，網址是作品資料夾名稱，例如 `0:直排測試書 EPUB`。線上來源同 Android 的資料庫 |
| 章節鍵 | 章節網址。本機來源是 `作品資料夾/檔名`，與備份相同 |
| 進度檔名 | 作品鍵的 UTF-8 位元組做 SHA-1，小寫十六進位，加 `.json` |
| 時間 | 1970-01-01 UTC 起算的毫秒數 |

## 3. 檔案內容

所有檔案都是 UTF-8 的 JSON 物件，都有 `"format": 1`。

- 讀取時忽略不認得的欄位。
- `format` 大於 1 的檔案整份略過，同步狀態裡顯示「其他裝置使用較新的版本」。
- 欄位缺少時用預設值。

### 3.1 暫存器

會被修改的資料都包成「暫存器」，附上這兩個欄位：

| 欄位 | 意義 |
|---|---|
| `t` | 這筆資料最後一次被修改的時間 |
| `d` | 修改它的裝置 id |

兩個暫存器比較時，`t` 大的較新；`t` 相同時，`d` 的字串比較大的較新。合併就是每一筆取較新的那個（後寫者勝）。

### 3.2 `device.json`

```json
{"format": 1, "device": "6f1c…", "name": "Pixel 9", "platform": "android", "app": "1.3.0", "written": 1764300000000}
```

`platform` 是 `android` 或 `ios`。這個檔案只用來在設定畫面顯示已同步的裝置。

### 3.3 `library.json`

```json
{
  "format": 1,
  "device": "6f1c…",
  "written": 1764300000000,
  "works": {
    "0:直排測試書 EPUB": {"favorite": true, "added": 1700000000000, "categories": ["小說"], "chapterFlags": 4097, "viewerFlags": null, "t": 1764300000000, "d": "6f1c…"}
  },
  "categories": {
    "小說": {"order": 0, "flags": 0, "t": 1764300000000, "d": "6f1c…"},
    "舊分類": {"deleted": true, "t": 1764300000500, "d": "6f1c…"}
  },
  "settings": {
    "pref_ebook_fontSize": {"type": "string", "value": "24", "t": 1764300000000, "d": "6f1c…"},
    "pref_reader_theme_key": {"type": "int", "value": 4, "t": 1764300000000, "d": "6f1c…"}
  },
  "progress": {"0:直排測試書 EPUB": 1764300000000}
}
```

**works**：每部作品一個暫存器，鍵是作品鍵。

| 欄位 | 預設值 | 意義 |
|---|---|---|
| `favorite` | false | 在書櫃中 |
| `added` | 0 | 加入書櫃的時間 |
| `categories` | [] | 所屬分類的**名稱**（各裝置的分類 id 不同），依名稱排序 |
| `chapterFlags` | 0 | 章節的排序與篩選（同 Android 的 chapter_flags） |
| `viewerFlags` | null | 閱讀模式等（同 Android 的 viewer_flags） |

**categories**：每個分類一個暫存器，鍵是分類名稱。

| 欄位 | 預設值 | 意義 |
|---|---|---|
| `order` | 0 | 排序 |
| `flags` | 0 | 分類的旗標 |
| `deleted` | false | 刪除的標記：分類刪除後留下這一筆，讓其他裝置也刪掉 |

重新命名等於刪掉舊名稱、加入新名稱。

**settings**：每個設定一個暫存器，鍵是偏好設定的鍵（Android 的鍵，iOS 也用同樣的鍵）。

| 欄位 | 意義 |
|---|---|
| `type` | `string`、`int` 或 `bool` |
| `value` | 值；`null` 表示這個設定被清除（回到預設） |

同步的鍵與 1.2.0 備份的設定範圍相同：排版設定的三層、閱讀器設定、書櫃設定。

**progress**：這台裝置每部作品進度檔的 `written`。其他裝置比對這個值，就知道哪些作品的進度要重新讀取。

### 3.4 `progress/<SHA-1>.json`

```json
{
  "format": 1,
  "device": "6f1c…",
  "written": 1764300000000,
  "work": "0:直排測試書 EPUB",
  "chapters": {
    "直排測試書 EPUB/zh-vertical.epub": {
      "progress": {"read": false, "page": 12, "left": 30, "t": 1764300000000, "d": "6f1c…"},
      "bookmark": {"value": true, "t": 1764200000000, "d": "6f1c…"},
      "position": {"locator": "{\"spine\":1,\"href\":\"OEBPS/text/ch02.xhtml\", …}", "t": 1764300000000, "d": "6f1c…"},
      "history": {"lastRead": 1764300000000, "duration": 120000}
    }
  }
}
```

每個章節有四個部分，都可以省略：

| 部分 | 欄位 | 合併方式 |
|---|---|---|
| `progress` | `read`、`page`（讀到的頁，從 0 起算）、`left`（剩下的頁數） | 暫存器 |
| `bookmark` | `value` | 暫存器 |
| `position` | `locator`：文字書的閱讀位置，與備份欄位 20101 相同的 JSON 字串；`null` 表示清除 | 暫存器 |
| `history` | `lastRead`（最後閱讀時間）、`duration`（閱讀時間） | 兩個欄位各取最大值，沒有 `t`、`d` |

### 3.5 `files.json`

```json
{
  "format": 1,
  "device": "6f1c…",
  "written": 1764300000000,
  "files": [
    {"work": "直排測試書 EPUB", "path": "zh-vertical.epub", "size": 48213, "t": 1764300000000},
    {"work": "漫畫測試", "path": "第01話/001.jpg", "size": 120934, "t": 1764300000000}
  ]
}
```

列出這台裝置上傳到 `files/` 的檔案。`work` 是本機來源的作品資料夾名稱，`path` 是資料夾內的相對路徑，以 `/` 分隔，最多兩層。

## 4. 判定本機的變更

各平台的同步程式從自己的資料（Android 的資料庫、iOS 的 library.json）取出「本機快照」：作品、分類、設定、章節的目前的值，沒有時間。

本機另外保存「基準」：

- 上一次同步後的合併結果。
- `applied`：上一次同步時，已經寫進本機資料的項目。

同步時，快照裡的每一項依下表變成暫存器：

| 情況 | 結果 |
|---|---|
| `applied` 有這一項，值與基準相同 | 沿用基準的暫存器（沒有改） |
| `applied` 有這一項，值與基準不同 | 本機改過：新暫存器，`d` = 自己，`t` 見下面的「改過的時間」 |
| `applied` 沒有這一項，值是預設值 | 不產生暫存器（讓其他裝置的值生效） |
| `applied` 沒有這一項，值不是預設值 | 第一次同步的資料：產生暫存器，`t` 用下面的「第一次的時間」，`d` = 自己 |

**刪除與清除**：

- 基準裡有、快照裡沒有的項目，沿用基準。這台裝置可能只是沒有這部作品或這個章節，例如還沒下載書檔，或是線上來源的作品在 iOS 上。
- 只有兩種情況算本機刪除，會產生 `t` = 現在的新暫存器：
  - `applied` 有的分類從快照裡消失：產生 `deleted: true`。
  - `applied` 有的設定從快照裡消失：產生 `value: null`。

**預設值**：

| 項目 | 預設值 |
|---|---|
| 作品 | 不在書櫃，而且沒有分類 |
| 進度 | 未讀，而且頁數是 0 |
| 書籤 | false |
| 位置 | 沒有 |
| 設定、分類 | 不存在 |

**改過的時間**：預設是現在。下列情況改用資料本身記錄的時間，讓離線時的修改不會蓋過其他裝置之後的修改：

| 項目 | 時間 |
|---|---|
| 進度 | 這個章節的 `lastRead` 比基準的 `t` 新時，用 `lastRead` |
| 位置 | 閱讀位置記錄的 `updatedAt` 比基準的 `t` 新時，用 `updatedAt` |
| 作品 | 在書櫃中、而且 `added` 比基準的 `t` 新（重新加入）時，用 `added` |

**第一次的時間**：

| 項目 | 時間 |
|---|---|
| 作品 | 在書櫃中時用 `added`，否則 0 |
| 進度 | 這個章節的 `lastRead`，沒有就是 0 |
| 位置 | 閱讀位置本身記錄的 `updatedAt` |
| 書籤、分類、設定 | 0 |

時間是 0 的資料，遇到其他裝置真正改過的資料一定比較舊。合併後，如果勝出的是這台裝置時間為 0 的資料，而且其他裝置都沒有這一項，就把它的 `t` 改成現在；這樣之後才加入同步的裝置，不會靠裝置 id 的大小蓋過它。結果是：

- 書櫃取兩邊的聯集。
- 進度以最近讀的為準。
- 設定在第一次同步時採用伺服器上已有的。

合併後，把與本機不同、而且本機有對應的項目寫進本機，記到 `applied`。歷史記錄寫入兩邊的最大值。合併結果成為新的基準。

裝置清單（`PROPFIND devices/`）在每次書櫃同步、作品同步、書檔同步時重新讀取，所以新加入的裝置不會被漏掉。

## 5. 流程

### 5.1 書櫃同步

在 App 開啟、回到前景、書櫃或設定改變時（稍等一下再一起送出）執行。

1. 確認資料夾存在：依序對 `Bookmania/`、`sync-v1/`、`devices/`、`devices/<自己>/`、`devices/<自己>/progress/`、`files/` 送 MKCOL。回應 201 或 405（已存在）都算成功。
2. `PROPFIND devices/`（`Depth: 1`），取得所有裝置 id。
3. 讀取其他裝置的 `library.json`。
4. 依第 4 節判定本機的變更，合併，把結果寫進本機。
5. 有些作品的進度要重新讀取：其他裝置的 `progress` 索引比基準裡記的新。對這些作品執行 5.2，只讀不寫。
6. 合併結果與上次上傳的不同時，`PUT` 自己的 `library.json`。第一次同步時也 `PUT` `device.json`。

### 5.2 作品同步

**開始閱讀時**，在讀取閱讀位置之前執行：

1. 讀取其他裝置這部作品的進度檔。404 表示那台裝置沒有這部作品的進度。
2. 合併，寫進本機。
3. 用合併後的位置開書。
4. 最多等 5 秒；逾時或連線失敗時，用本機的進度開書，同步改到背景繼續。

**離開閱讀時**（包括切到別的 App、App 進入背景）：

1. 讀取其他裝置的進度檔並合併。
2. 合併結果與上次上傳的不同時，`PUT` 自己的進度檔。
3. 更新 `library.json` 的 `progress` 索引，`PUT` `library.json`。

**連不上時**，記下「這部作品待同步」，下次書櫃同步時一起處理。

### 5.3 書檔同步

在書櫃同步之後執行，預設只在不計流量的網路下進行。

1. 讀取其他裝置的 `files.json`。
2. 列出本機書櫃中本機來源作品的檔案：資料夾內的檔案，以及子資料夾內的檔案；以 `.` 開頭的隱藏檔略過。
3. 依下表處理每個檔案：

| 檔案的情況 | 動作 |
|---|---|
| 本機有，所有裝置的清單都沒有 | 上傳到 `files/<作品>/<路徑>`，需要的資料夾先 MKCOL，記進自己的 `files.json` |
| 清單裡有，本機的書櫃有這部作品但沒有這個檔案 | 下載到本機來源的作品資料夾 |
| 兩邊都有、大小相同 | 不動作 |
| 兩邊都有、大小不同 | 衝突：不動作，在同步狀態裡列出 |

4. 不刪除伺服器上的任何檔案。
5. 下載前檢查清單裡的名稱。下列任何一種都拒絕下載，在同步狀態裡列出：
   - 作品名稱或路徑的任一段是空的、`.`、`..`，或以 `.` 開頭；
   - 含有 `/`、`\`、NUL 或其他控制字元；
   - 任一段超過 255 bytes；
   - 路徑超過兩層。

## 6. WebDAV 的請求

- 網址必須是 `https://`，否則不同步。
- 驗證方式用 Basic，每個請求都帶上。只接受系統信任的憑證。
- 路徑的每一段以 UTF-8 做百分比編碼。
- 用到的方法：`MKCOL`、`PROPFIND`、`GET`、`PUT`。
  - `PROPFIND` 的內容要求 `resourcetype`、`getetag`、`getcontentlength`。
  - 回應的 `href` 可能是完整網址或絕對路徑，比對時先解碼，再取最後一段。
- 解析伺服器回應的 XML 時關閉 DTD 與外部實體，因為回應是不可信的輸入。

| 回應 | 處理 |
|---|---|
| 2xx | 成功 |
| 404 | 不存在 |
| 401、403 | 帳號或權限錯誤：停止同步，在設定畫面顯示 |
| 其他狀態，或連線錯誤 | 這次同步失敗，下次再試 |
