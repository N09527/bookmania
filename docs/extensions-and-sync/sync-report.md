## 1. 需求（重述版本）

你的需求與決定（重述版本）：

- 透過 WebDAV 同步書櫃，並在開始閱讀與離開閱讀時同步進度，讓不同裝置與平台可以接續閱讀。
- 同步全部：書櫃與進度、設定、書檔本身。
- 伺服器只接受 HTTPS。
- 先做同步，再做 iOS 擴充來源。

## 2. 完成的內容

### 2.1 同步核心（Kotlin `core/sync`、Swift `BookmaniaCore/Sync`）

S-1 已完成，這次的修改：

- **書櫃同步也送出本機改過的進度**：
  - 例如在書櫃標成已讀，或開啟同步之前就讀過的書。
  - 只用本機資料判定，沒改過的作品不發出請求。
  - `library.json` 在全部作品處理完之後才送一次。
- **閱讀位置改成比較內容**：
  - 兩個平台寫出的 JSON 鍵順序不同。
  - 逐字比對會讓舊位置以「現在」的時間蓋過其他裝置較新的位置（第 4 節第 2 項）。
- **伺服器上這台裝置的資料不見時，全部重新送出**（第 4 節第 5 項）。
- **iOS 的連線不使用快取**：避免讀到快取裡舊的 `library.json`。

### 2.2 Android

- **設定畫面**：「設定 > WebDAV 同步」，內容如下。
  - 伺服器網址、帳號、密碼；測試連線、儲存。
  - 同步開關、同步書檔、只在 Wi-Fi 傳書檔。
  - 立即同步、上次結果、衝突與沒有傳送的書檔。
- **密碼**：以 Android Keystore 的金鑰加密保存。
- **同步時機**：
  - App 開啟、回到前景時。
  - 書櫃或設定改變後 15 秒。
  - 開書前：最多等 5 秒（文字與圖片閱讀器都是）。
  - 離開閱讀或切到其他 App 時：交給背景工作，連不上時自動重試。
- **書檔**：使用本機來源讀取的所有資料夾。

### 2.3 iPhone／iPad

- **設定畫面**：「更多 > WebDAV 同步」，內容與 Android 相同。
- **密碼**：存在鑰匙圈（只限這台裝置，第一次解鎖後可讀，讓背景同步能完成）。
- **同步時機**：
  - App 開啟、回到前景時。
  - 書櫃或設定改變後 15 秒。
  - 開書前：最多等 5 秒，期間顯示轉圈。
  - 關閉閱讀器、App 切到背景時：會向系統要求背景時間，讓同步做完。
- **書檔**：打開「只在 Wi-Fi 下傳送書檔」時，行動網路、個人熱點與低數據模式下不傳。
- **權限**：加上區域網路權限的說明文字。

### 2.4 授權

- 沒有新增隨 App 發布的第三方元件。
- Android 的同步核心使用 OkHttp、okio 與 kotlinx.serialization：App 原本就有這三個，OkHttp 是 `core/main` 的依賴，okio 隨它而來。
- iOS 只用系統的 Network 與 Security 框架。
- 測試用的 WsgiDAV（MIT）只在這裡測試時使用，不隨 App 發布。

### 3.2 模擬器上的兩台裝置

**環境**：

- **Android**：模擬器，Android 8.0，沒有硬體加速。
- **伺服器**：這裡的 WsgiDAV 4.4.1。
  - 用 HTTPS 與測試用的 CA。
  - CA 裝在模擬器的使用者憑證中。
- **第二台裝置（代替 iPhone）**：一個在 Linux 上執行的小程式。
  - 用的是 iOS 版的同步程式：`LibrarySyncAdapter`、`LibraryStore`、`SyncEngine`、`URLSessionTransport`。
  - 它連的是同一個資料夾，但走只聽本機的 HTTP。原因是 Linux 版 URLSession 無法指定測試 CA。
  - 所以 iOS 端的 HTTPS 沒有測到（第 5 節）。

| 項目 | 結果 |
|---|---|
| 書櫃同步送出既有進度 | 啟動後書櫃同步送出 3 部作品的進度檔：章節進度、2 個閱讀位置、閱讀記錄 |
| 第二台裝置第一次同步 | 收到 3 部作品、5 個章節的進度、2 個位置、閱讀記錄 |
| 開書前取得進度 | 第二台裝置把直排測試書設在第 30 段並送出；模擬器本機的位置是第 8 段，打開後停在含第 28～32 段的那一頁 |
| 離開時送出進度 | 翻到第 33 段後離開，9 秒後伺服器上的進度檔更新（位置、閱讀記錄），`library.json` 的索引也更新；第二台裝置的書櫃同步取回第 33 段 |
| 設定：第二台 → Android | 背景顏色（`pref_reader_theme_key` = 2）寫進模擬器的設定 |
| 設定：Android → 第二台 | 在模擬器介面打開「捲曲翻頁」，6 秒後送出，第二台裝置收到 `true` |
| 第二台新增的作品 | 「同步新書」（AZW3＋EPUB 兩冊）在 Android 建立為書櫃中的作品；書檔下載後出現 2 個章節 |

## 4. 找到並修正的問題

1. **既有的進度不會送出**：書櫃同步原本只處理其他裝置改過的作品與待同步的作品。修正後也送出本機改過的進度（`1e43c71`）。
2. **跨平台的閱讀位置被誤判為本機修改**（`ffc91a1`）：
   - **發現經過**：第二台裝置收到 Android 的位置後，下次同步卻把這本書的進度送出。它根本沒有改過這本書。
   - **原因**：iOS 把位置解析成結構保存，再寫回 JSON 時鍵的順序不同，逐字比對就認定「改過」。
   - **後果**：會用現在的時間重新宣告舊位置，蓋過另一台裝置之後讀到的位置。
   - **修正**：兩邊改成比較 JSON 的內容，並加了共用情境。
3. **Android 的同步工作不會執行**（`6dcb06a`）：
   - 工作原本要求「系統確認可上網的網路」，家用伺服器所在的網路不一定符合。
   - 改成不設網路條件，失敗時重試。
   - 同一個提交也修正了：打開同步開關時沒有開始同步。
4. **Android 的書檔只看一個資料夾，失敗也不顯示**（`74a3ec4`）：
   - 本機來源會從多個資料夾讀書，同步卻只看儲存位置的那一個。
   - 書在其他資料夾時，沒有檔案可上傳；下載也默默失敗（紀錄是 `no local source folder`）。
   - 修正後使用同一組資料夾，失敗的書檔會記錄並顯示在同步畫面。
5. **伺服器的資料被刪除後不會重新送出**（`ccae901`）：
   - 寫使用說明時發現。
   - 裝置只比對「上次上傳的內容」，所以伺服器清空後，沒變的書櫃、進度與書檔都不會再送。
   - 修正後，書櫃同步每次重新確認資料夾；自己的資料夾需要重新建立時，就全部重新送出。

## 5. 沒有驗證的項目

- **iOS App 本身沒有執行過**：這裡沒有 Mac，只確認了 GitHub 上的編譯。以下都需要在你的裝置上確認：
  - 設定畫面、鑰匙圈、開書前的轉圈與 5 秒上限、關閉與切到背景時的送出。
  - 背景時間、Wi-Fi 判斷、區域網路權限。
  - HTTPS（App Transport Security）。
  - 自簽憑證：需要安裝描述檔並開啟完整信任，見使用說明第 4 節【二手】。
- **Android**：
  - 計量網路下不傳書檔：模擬器使用的是 Wi-Fi，計量網路的情況沒有測到。
  - 分類同步：模擬器上沒有分類，只有單元測試。
  - 書檔衝突（同名不同大小）：只有單元測試。
  - 伺服器很慢（而不是拒絕連線）時的 5 秒上限：只測了連線被拒的情況。
- **大型書櫃的耗時**：書櫃同步會逐一比對每部作品的進度，作品很多時的時間沒有量過。
- **其他伺服器**：只用 WsgiDAV 測試過。

## 6. 請你在裝置上檢查

1. **準備**：
   - 準備一台 HTTPS 的 WebDAV 伺服器。
   - Android 與 iPhone／iPad 都更新到 1.3.0。
2. **設定**：兩邊都設定同一個伺服器與帳號，按「測試連線」→「儲存」→打開同步。
3. **進度**：
   1. 在 Android 讀一本書，翻幾頁後離開閱讀。
   2. 在 iPhone 打開同一本書，應停在同一頁附近。
   3. 再反過來做一次。
4. **書檔**：只在一邊放一本新書並加入書櫃。另一邊回到前景（需要 Wi-Fi）後，應出現這本書。
5. **設定**：在一邊改背景顏色或排版。約 15 秒後，讓另一邊回到前景，再打開閱讀器確認。
6. **離線**：
   1. 關掉網路讀幾頁、離開閱讀。
   2. 恢復網路，回到 App。
   3. 確認另一邊取得了這段進度。
7. **有問題時**：同步畫面會顯示上次的錯誤，請把文字告訴我。
