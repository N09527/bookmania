## 1. 實作

### 1.1 字體加粗

- 設定模型（`EbookSettings`）新增 `bold`，鍵 `bold`。全部書籍的值存在新的偏好設定鍵 `pref_ebook_bold`；作品與檔案層存在既有的覆寫 JSON 中。沒有改變任何既有鍵。
- 殼層（`reader.js`）在打開時加上 `body, body * { font-weight: bold !important; }`。對所有元素加，是因為有些書把段落指定為一般粗細，只加在 `body` 會被書本身的樣式蓋掉。
- 字型本身有粗體字面時用它；沒有時（例如只匯入一個字重的字型）由 WebView 合成粗體。
- 改變後重新排版，回到同一個字（和其他排版設定相同）。
- 面板：「文字」分頁字體清單下方，一行「字體加粗」與開關；較近的層級設定了這一項時，和其他項目一樣顯示提示。
- 新字串：英文「Bold text」、正體中文「字體加粗」。

### 1.2 中縫陰影：文字閱讀器

- 新的 package `yokai.gutter`：
  - `GutterShadow`：一條垂直的 `LinearGradient` 色帶，寬 64 dp，中線最暗（30% 黑），往兩側變淡到透明，左右對稱。
  - `GutterShadowView`：疊在 WebView 上方（同一個容器），不接收觸控，不參與無障礙。
  - `GutterPreferences`：兩個新偏好設定鍵，`pref_ebook_gutter_shadow`（文字閱讀器）與 `pref_bookmania_pager_gutter_shadow`（漫畫閱讀器），預設都是開啟。
- 位置：殼層的 `status()` 多回報兩欄間隙的中央（CSS px）與排版用的寬度；只有顯示兩欄時才有。閱讀器換算成像素後畫在那裡。
- 翻頁動畫：陰影在 WebView 上方、同一個視窗內，所以翻頁動畫複製頁面時，複本也帶著陰影，捲曲與滑動時陰影跟著頁面。
- 旋轉、改排版設定後，等新的排版完成才重新放陰影；改成單欄就消失。
- 設定：排版面板「版面」分頁「雙欄」下方，「中縫陰影」開關，附說明「雙欄時在兩欄中間加上陰影，像實體書的中縫。所有書共用，不受上方選擇的範圍影響。」（和翻頁動畫一樣，不分三層）。

### 1.3 中縫陰影：漫畫閱讀器的雙頁模式

- 雙頁模式把兩頁拼成一張圖（上游 `ImageUtil.mergeBitmaps`），兩半一樣寬，所以接縫在圖的正中央。
- `PagerGutterShadow`：陰影畫在圖片元件自己的覆蓋層（`ViewOverlay`）上，每次圖片重畫時，依圖片當下的縮放與位置算出接縫在畫面上的位置，只畫在圖片的高度內。放大、拖動、甩動時跟著接縫。
  - 第一版是另一個疊在圖片上的圖層，在每一幀繪製前讀取圖片的位置。圖片的縮放動畫是在它自己繪製時才前進，所以那一版在動畫中可能每隔一幀慢一步。改成覆蓋層後，陰影和圖片在同一次繪製中完成。
  - 設定開關改變時（閱讀器設定或「設定 > 閱讀」），經由偏好設定的變更通知重畫圖片。
- 只有真的拼成兩頁時才有陰影；單獨顯示一頁（封面、橫幅的跨頁圖、最後落單的一頁）沒有。
- 對上游檔案的修改：
  - `PagerPageHolder.kt`：記錄這一頁是否拼了兩頁（拼接的那一行之後設為是），圖片載入後交給 `PagerGutterShadow`（+8／−1 行，含 import 與註解）。
  - `reader_paged_layout.xml`、`ReaderPagedView.kt`：閱讀器設定的翻頁模式選項中，「反轉雙頁」下方加「中縫陰影」開關，顯示條件和「反轉雙頁」相同（版面不是「單頁」時）。
  - `SettingsReaderController.kt`：設定 > 閱讀，「捲曲翻頁」下方加「中縫陰影」與說明「雙頁模式中，在兩頁相接處加上陰影，像實體書的中縫。」
- 捲曲翻頁時，陰影同樣在複本中。

### 1.4 我自行決定的細節【決定】

1. **陰影的位置跟著兩欄的間隙**：你寫「直接在螢幕正中央」。左右邊距相同時（預設 20／20）間隙就在螢幕正中央；左右邊距不同時，間隙會偏離中央，陰影放在螢幕中央會壓到一欄的文字，所以改放在間隙的中央。
2. **陰影的大小與深淺**：寬 64 dp、中線 30% 黑。兩欄的間隙是 40 dp，較深的部分在間隙內，文字邊緣只有很淡的部分（約 3%）。可以調整。
3. **兩個閱讀器各一個開關**：文字閱讀器在排版面板；漫畫閱讀器在閱讀器設定與「設定 > 閱讀」（和第 5.5 階段的「捲曲翻頁」放在一起）。
4. **漫畫閱讀器只做翻頁模式的雙頁**（左至右、右至左、直向翻頁）；長條模式的雙頁沒有加，和捲曲翻頁的範圍相同。
5. **加粗時，書中原本用粗體表示的強調**（`<b>`、`<strong>`）和內文一樣粗，看不出強調。

### 3.4 這一輪測試工具的問題（不是 App 的問題，都已修正並重跑）

第一輪（當時的程式碼：文字閱讀器的陰影位置以「寬度比例」換算，漫畫的陰影是另一個圖層）35 項中 32 項通過，沒通過的 3 項都是腳本的問題；漫畫那一項沒通過後，該步驟其餘的檢查沒有執行。之後單獨重跑漫畫兩次，又找到兩個腳本問題。全部問題如下：

1. **實機**：兩項功能與回歸測試都只在 Android 8.0 模擬器（WebView 69，沒有硬體加速）上跑過。實機上的粗體字形，以及陰影在不同螢幕密度與亮度下的樣子，都沒有看過。請你在手機上看的項目列在 6.4。
2. **漫畫閱讀器的其他模式**：只測「左至右」翻頁的雙頁。「右至左」「直向翻頁」的雙頁、「反轉雙頁」、摺疊螢幕的鉸鏈間隙都沒有測。【推論】這些模式的兩頁同樣由 `ImageUtil.mergeBitmaps` 拼成左右兩半等寬的圖，接縫一樣在圖的正中央。
3. **漫畫閱讀器開啟「裁切邊框」**：沒有測。【推論】圖片元件顯示的是裁掉外側留白後的圖；兩頁外側留白寬度不同時，畫面上圖的中央不等於接縫，陰影會偏離接縫。
4. **深色背景**：沒有測。【推論】陰影是黑色半透明，背景是黑色時看不出來；灰色背景時比白色淡。
5. **release 版**：兩項功能在 release 版上只量了 3.6 列出的情況，偏好設定由腳本直接寫入。面板上的操作、三層設定、重開後保留、閱讀位置、捲曲中的陰影、漫畫的原始尺寸與拖動，只在 debug 版上驗證；兩者的 App 程式相同，差在 release 的 R8 縮減與簽章。
6. **加粗**：
   - 匯入的字型本身已是粗體時，打開加粗會再合成一次，變得更粗（依程式推論，沒有測）。
   - 書中原本用粗體表示的強調，打開加粗後和內文一樣粗（1.4 第 5 點）。
7. **長條模式的雙頁**：依 1.4 第 4 點沒有加陰影。
8. **備份與還原**：三個新設定是 App 偏好設定，【推論】會隨既有的「App 設定」備份；沒有實測備份與還原這三個鍵。
9. **4.2 的捲曲期限**：實機上開書後第一次捲曲建立繪圖層要多久，沒有量過。
