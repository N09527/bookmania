## 1. 實作

### 1.1 作品頁的用字

- 作品頁簡介上方的標題原本是字串 `about_this_`：「關於此%1$s」，%1$s 是作品類型（日漫、韓漫、漫畫…）。改為：
  - 正體中文：「內容簡介」。
  - 英文：「About this book」（原本是「About this %1$s」）。
  - 所有作品類型都一樣。程式仍傳入作品類型，字串裡沒有它的位置，所以不會顯示。其他語言的翻譯沒有改。
- 「共 N 章」是字串 `chapters_plural` 的正體中文翻譯「共 %1$s 章」，改為「共 %1$s 冊」。依你的選擇，用到它的地方都會改變【已查證：程式碼】：
  - 作品頁章節清單上方的標題。
  - 書櫃依「總章數」排序時，拖動捲軸出現的提示。
  - 統計頁「長度」的分類名稱，以及從這些分類打開的書櫃標題。
  - 模擬器上只看了作品頁（3.1）。
  - 英文仍是「N chapters」（你沒有要求改英文）。
- 這三行都在上游的翻譯檔（`i18n/.../base/strings.xml`、`zh-rTW/strings.xml`、`zh-rTW/plurals.xml`），每處加了一行註解標明是 Bookmania 的修改，方便日後合併上游。

### 1.2 雙欄時的左右邊距

原因【已查證：程式碼與模擬器】：
- 殼層規定雙欄時每欄至少 120 dp：每欄寬 =（畫面寬 − 左 − 右 − 40）÷ 2，小於 120 就改為單欄。
- 這部模擬器直向畫面寬 412 dp，左右邊距合計超過 132 就變單欄。在排版面板上實際操作：右邊距 60 時是雙欄，82 時變單欄（頁數 20 → 10），70 又是雙欄；左邊距 80 時單欄，38 時雙欄。
- 寬 360 dp 的手機，合計超過 80 就會變單欄，例如左右各 40 以上。所以在雙欄時調左右邊距，越過門檻就會在單欄與雙欄之間來回跳。

修正（你選擇「雙欄時限制邊距上限」）：
- 面板：設定要求這個畫面顯示雙欄時（「雙欄」選「開啟」，或「僅橫向畫面」時的橫向），左、右邊距的滑桿與輸入欄上限依畫面寬度計算，讓每欄至少 120 dp。左邊距的上限 = 合計上限 − 右邊距，右邊距同理。
  - 面板顯示「雙欄時，左右邊距合計最多 N dp（每欄至少 120 dp）。」
  - 只在上限真的會限制到時顯示：橫向畫面的上限超過 120 + 120，就不顯示。
- 殼層：已存的邊距若超過上限（例如在單欄或橫向時設的），雙欄時改為按比例縮小實際使用的左右邊距，維持兩欄。存起來的值不變；面板另外顯示「目前合計 N dp，雙欄時會按比例縮小。」
  - 只有畫面窄於 280 dp（120 + 120 + 40）時才會是單欄。
- 殼層的狀態多回報四個值：是否要求雙欄、合計上限、實際使用的左右邊距。閱讀器把上限傳給面板。

### 1.3 排版數值的輸入欄

- 排版面板 9 個數值項目的滑桿右邊，各有一個常駐的輸入欄（你選擇「滑桿旁常駐輸入欄」「全部排版數值」）：
  - 文字分頁：字級、行距、字距、首行縮排、段落間距。
  - 版面分頁：上、下、左、右邊距。
  - 單位寫在輸入欄後面（dp、em、字）；行距與字級沒有單位，和原本的顯示相同。
- 輸入：
  - 點輸入欄時，原值會全選，直接輸入就取代它。
  - 按鍵盤的「完成」或離開輸入欄時套用。
  - 超出範圍或格式不對時不套用，下方顯示可輸入的範圍（例如「可輸入 12～48 的整數」）；這時離開輸入欄，會恢復原值。
- 拖動滑桿時，輸入欄的數字跟著變。首行縮排與段落間距在「依書籍」打開時沒有輸入欄，和原本不顯示數值相同。
- 精度：滑桿仍照原本的級距移動，輸入欄可以更精確。
  - 字級是整數。
  - 邊距是整數 dp：原本只能是偶數，現在可以輸入單數。
  - 行距、字距、首行縮排、段落間距可到小數點後兩位。
  - 設定模型讀取時不再把值改成滑桿的級距，只限制範圍與精度；既有的值意義不變。
- 鍵盤：
  - 文字閱讀器的視窗設為 `adjustResize`，面板加上依鍵盤高度留白。鍵盤出現時，直向的面板移到鍵盤上方，橫向的側邊面板變短。
  - 預設的全螢幕模式下，書頁本身不會改變大小，也不會重新排版【已查證：模擬器】。
- 新字串（英文、正體中文）：可輸入的範圍兩種（數字、整數），雙欄邊距的說明兩種。

### 1.4 過程中發現並修正的問題：用輸入欄改值後，雙欄的左欄被捲到章末

- 現象【已查證：模擬器】：雙欄時用輸入欄把字級改成 24、按「完成」。之後右欄正確，左欄卻顯示章末的「註腳測試／註一；外部連結：example.com…」，左邊緣的字被切掉。左欄捲動位置是 4121，應該是 0。用滑桿改同樣的值，不會發生。
- 原因【已查證】：
  - 按「完成」時，輸入欄原本是「清除焦點」。
  - 之後左欄文件中取得焦點的元素，變成章末的一個連結（`activeElement` 是 A）。瀏覽器把它捲進畫面，4121 正好是讓那個連結出現的位置。
  - 為什麼清除焦點會讓書頁裡的連結取得焦點，沒有查明：WebView 本身設為不可取得焦點。
- 修正：按「完成」時，把焦點交給面板本身，不清除焦點。修正後同樣的操作，兩欄是 0／190，焦點在 BODY【已查證】。另外試過兩種情況，兩欄位置都正常：輸入欄有焦點時直接關閉面板，以及用返回鍵收起鍵盤。
- 這是第 8 階段新加的輸入欄才有的情況，第 7 階段的 APK 沒有輸入欄。

### 1.5 我自行決定的細節【決定】

1. **輸入精度**：見 1.3。原本邊距只能是偶數，是滑桿的級距 2 dp 造成的；直接輸入時讓單數也能設。
2. **超出範圍時不套用**，而是顯示可輸入的範圍；不自動改成最接近的值。
3. **按「完成」後鍵盤收起**，焦點留在面板上。
4. **返回鍵**：輸入欄有焦點時，第一次按返回鍵收起鍵盤，第二次取消輸入欄的焦點（這兩次【已查證：模擬器】，面板仍開著）。第三次才關閉面板，閱讀器仍在前景（【已查證：模擬器】，3.6 的三輪都相同）。前兩次是系統鍵盤與 Compose 輸入欄的標準行為，我沒有更改。
5. **雙欄的上限只在設定要求雙欄時套用**。單欄（「雙欄」關閉，或「僅橫向畫面」時的直向）仍可設到 120。
6. **英文的章數**仍是「N chapters」，你只要求改中文的「章」。

### 3.6 鍵盤出現與面板移動的時間（錄影）

3.2 的面板要等幾秒才移到鍵盤上方，我想分清楚是這部模擬器整體太慢，還是 App 的問題，所以另外錄影量測【已查證：模擬器、debug 版】。

## 5. 沒有驗證的項目

1. **實機**：這次的修改只在 Android 8.0 模擬器（WebView 69，沒有硬體加速）上驗證。實機的輸入法（例如 Gboard、注音）、鍵盤高度、面板移到鍵盤上方的速度，都沒有看過。請你在手機上看的項目在 6.4。
2. **面板移到鍵盤上方的時間**（3.2、3.6）：在這部模擬器上，面板在鍵盤畫完之後才移動，要等好幾秒；錄影會讓模擬器更慢，無法量出準確的時間。手機上是否也要等，沒有驗證。
3. **其他螢幕寬度**：雙欄的上限只在寬 412 dp（直向）與 732 dp（橫向）量過。其他寬度依公式「寬 − 280」計算【推論：程式碼】，例如寬 360 dp 的手機，左右合計上限是 80 dp；寬度小於 280 dp 時仍會改為單欄。
4. **直排書與「僅橫向畫面」**：雙欄邊距只用橫排測試書、「雙欄」選「開啟」檢查。【推論：程式碼】殼層計算上限時不分直排橫排；「僅橫向畫面」時，直向畫面是單欄、沒有上限，橫向畫面和 3.3 的橫向相同。都沒有實測。
5. **輸入欄的其他操作**：只用模擬器的系統鍵盤（數字鍵盤）與 `input text` 輸入。手機輸入法的小數點與逗號（程式把逗號當小數點）、貼上、長按選字都沒有試。
6. **release 版**：輸入欄與雙欄上限只在 debug 版上驗證。release 版檢查了作品頁的英文字串（3.5）、煙霧測試與第 7 階段的兩項功能。兩者的 App 程式相同，差在 R8 縮減與簽章。
7. **「共 N 冊」在作品頁以外的地方**：書櫃的捲軸提示、統計頁「長度」與從它打開的書櫃標題，用的是同一個字串【已查證：程式碼】，沒有在模擬器上看過。
8. **其他語言**：英文與正體中文以外的翻譯沒有改，也沒有看。例如簡體中文仍是「简介」「N 章」，日文仍是「この（作品類型）について」。
9. **滑桿最右端的點擊**（3.4 第 4 點）：模擬器上點在右邊距滑桿最右端沒有反應，原因沒有查明；拖到最右端可以。其他滑桿與實機上是否一樣，沒有試。
