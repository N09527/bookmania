### 1.2 三層設定（第 4 題：全域 → 作品 → 單一檔案）

- 面板上方選「全部書籍／這部作品／這個檔案」，之後的修改寫進那一層；近的一層優先，沒設定的項目沿用上一層。
- 面板顯示「從所選層級往上合併」的值。若更近的一層也設定了同一項，該項下方以紅字標示「『這部作品』也有設定，這本書以那一層為準」，避免改了卻看不到變化（截圖 `s3-17`）。
- 「清除這一層的設定」：清掉該層全部設定，恢復沿用上一層（全域層則回到預設值）；該層沒有設定時按鈕停用。
- 開啟面板時預設選：這本書已有「這個檔案」的設定就選它，否則有「這部作品」的設定就選它，都沒有就選「全部書籍」【決定】。
- 儲存【已查證：模擬器上的偏好設定檔】：
  - 全域：`pref_ebook_<項目>`，例如 `pref_ebook_fontSize`。
  - 作品／檔案：各一個 JSON 字串，鍵為 `pref_ebook_override_<SHA-1>`；SHA-1 取自（層級、來源 id、作品網址、章節網址）。JSON 內同時存放 `_source`、`_manga`（檔案層另有 `_chapter`）。用網址而不用資料庫 id，是因為還原備份後 id 會變、網址不變。
  - 以上都是一般偏好設定，會隨既有備份進出：`PreferenceBackupCreator.toBackupPreferences()` 只排除 `__APP_STATE_` 開頭的鍵，備份選項「App 設定」預設開啟【已查證：讀程式碼；沒有實際做一次備份與還原】。
  - 沒有新增資料庫欄位或 migration，沒有改動備份 protobuf，沒有改變任何既有偏好設定鍵的意義。

### 1.3 字型匯入（第 8 題）

- 「匯入字型…」用系統檔案選擇器（`ACTION_OPEN_DOCUMENT`），不需要儲存空間權限。
- 檢查檔案內容而非副檔名：只接受 TrueType／OpenType（檔頭 `0x00010000`、`true`、`OTTO`）；TTC、WOFF、WOFF2 與其他檔案顯示「不是支援的字型，只能匯入 TTF 或 OTF 檔。」；上限 64 MB。已知檔案大小時只配置一個剛好大小的緩衝區（見第 4 節第 9 點）。
- 直排資訊檢查：`vhea`＋`vmtx`（直排度量）與 GSUB 的 `vert`／`vrt2`（直排字形）。缺少時跳出提醒並列出缺少的表，使用者可選擇仍要匯入（設計 4.5 第 1 點「提示但仍允許使用」，截圖 `s3-31`）；清單中該字型下方標示「沒有直排資訊」。
- 字型名稱讀 `name` 表，優先順序：繁中（台灣）→ 繁中（香港、澳門）→ 簡中 → 英文 → 其他；讀不到時用檔名。
- 存放：App 私有目錄 `files/ebook-fonts/<32 位十六進位 id>.ttf|otf`（設計 5.6 原寫 `files/fonts/`，改用較明確的名稱【決定】）。清單存在 `__APP_STATE_ebook_fonts`，與字型檔一樣**不進備份**；在另一台裝置還原備份後，指向不存在字型的設定會自動退回「書籍指定」。
- 書籍只能以 `https://appassets.androidplatform.net/fonts/<id>` 取得字型：請求處理器只接受 32 位小寫十六進位 id，而且必須在清單內，其他一律 404。
- 刪除前會確認；正在使用它的書改用書籍指定的字體。匯入後不會自動選用，需要再點一下【決定】。

### 1.4 我自行決定的細節【決定】

1. **面板不蓋住整頁**：設計寫「底部面板」，我做成閱讀畫面內的非強制（non-modal）面板：「文字／版面」分頁與關閉鈕在同一列，內容區最多佔螢幕高度 30%，直向畫面時頁面上半部保持可見，調整時即時重新分頁並回到同一個字。點頁面、按返回鍵或「×」關閉。
2. **面板一律留在導覽列區域上方**（即使系統列隱藏）：否則滑出的導覽列會蓋住最後一列，而在手勢導覽的手機上，螢幕最下緣是系統手勢區。
3. **字距 0 不覆寫書籍**：設定表的預設是 0。若 0 也強制套用，書中刻意加寬字距的標題等會被改掉，所以 0 代表「不額外加字距」，大於 0 才覆寫。
4. **滑桿放開才套用**：拖動時只更新數字，放開後才重新分頁，避免每移動一格就重排一次；滑桿不畫刻度點（邊距有 60 格）。
5. **翻頁方向放在「版面」頁**，與書寫方向並列，並附說明「自動：直書右開，橫書左開。」

## 3. 模擬器驗證

環境與第 2 階段相同：Android 8.0（API 26）x86_64 模擬器，純軟體模擬（沒有硬體加速）；WebView 為 Chrome 69.0.3497.100；畫面 1080×1920（網頁視窗 412×732 CSS px）；安裝 `app-bookmania-x86_64-debug.apk`；App 語言設為繁體中文。腳本與完整結果：`docs/ebook-reader/tools/stage3/`、`screenshots/stage3/check-results.jsonl`。

## 4. 過程中發現並修正的問題

1. **工具列副標題被截一半**（第 2 階段就存在）：工具列加上狀態列內距後高度沒有跟著增加。改為最小高度＝動作列高度＋內距。
2. **頁碼壓在導覽列上**（全螢幕模式下顯示選單時，第 2 階段就存在）：底部外距加上系統列高度。

- **Release 版**：只做了第 2 節的煙霧測試，字型匯入與各數值設定沒有在 release 版測試。
- **「系統襯線」在此模擬器上看不出差異**【已查證：Android 8 模擬器】：選了之後書籍文件的 `font-family` 確實變成 `serif`，也重新排版，但畫面與先前完全相同。系統的 `fonts.xml` 中繁中（zh-Hant）只有 Noto Sans CJK，沒有中文襯線字型；量測書中英文字「WebView」的寬度，也與無襯線字型相近、與 Noto Serif 不同，表示繁中文件連英文也用同一個字型繪製。較新的 Android 是否內建中文襯線字型未查證；目前要明體／宋體的效果需匯入字型。
- **備份與還原**：設定會進備份是讀程式碼確認的，沒有實際做一次備份與還原。
- **字型名稱的語言優先順序**：只用單元測試的測試字型驗證（繁中名稱「書狂測試直排」）。Noto Serif CJK TC 雖有繁中（0x0404）名稱記錄，內容也是「Noto Serif CJK TC」，所以模擬器畫面上看不出優先順序的效果。
- **書籍用絕對單位指定字級時**【推論，未用實際書籍測試】：字級設定是改 `html` 的 `font-size`，以 em／rem／百分比指定字級的書會跟著縮放；若書籍以 px 等絕對單位指定，那些文字不會隨字級設定改變。
- **其他階段的項目**：雙欄（階段 4）、閱讀位置與已讀紀錄、目錄與進度滑桿（階段 5）、翻頁動畫等都還沒做。

## 7. 決定後的修改

### 7.1 大型字型的載入速度（提前處理）【已查證：模擬器】

做法：

- 匯入的字型在閱讀器殼層只載入一次，建立一個 FontFace。之後每個章節檔的書籍文件，都加入這個已載入的字型。
- 開啟章節檔時，字型與文件同時開始載入。
- 無法共用時（瀏覽器不支援把字型加入另一份文件）才退回原本的做法，由每個文件各自以 `@font-face` 載入。
- 快取設定（書籍資源 `no-store`、WebView 不使用快取）沒有改變。

先在 WebView 69 上確認可行：

- 殼層建立的 FontFace 可以加入書籍文件，文件中的文字確實使用它：`fonts.check` 為真，同一段文字用它量出的寬度也與系統字型不同。
- 加入後重新排版約 1.4 秒。對照：同一個字型網址另外再載入一次要 16 秒（第一次 28 秒），這就是修改前每個章節檔都要付出的成本。

結果：同一本直排書連續開三個章節檔，每個檔案的排版耗時（殼層 `status().ms`），App 冷啟動。

| | 第 1 個章節檔 | 第 2 個 | 第 3 個 |
|---|---|---|---|
| 修改後，使用 25 MB 匯入字型 | 19.6 秒 | 5.0 秒 | 6.0 秒 |
| 不使用匯入字型（對照） | 6.5 秒 | 4.9 秒 | 3.2 秒 |
| 修改前，使用匯入字型（3.3 節） | 42.7 秒、51.3 秒（兩次） | 沒有量 | 沒有量 |

- 修改後，只有第一個章節檔需要載入字型；之後的章節檔與不使用匯入字型時相近。
- 修改前沒有量第 2、3 個章節檔。依當時的實作，每個文件都會重新載入字型，所以【推論】每個章節檔都要多付出上述的重新載入時間。
- 模擬器數字起伏大，只能看量級；實機沒有量測。
- 另一次手動量測：第 2 個章節檔 2.6 秒。

### 7.2 橫向畫面改用側邊面板【已查證：模擬器】

- 直向：維持底部面板。
- 橫向：全高的側邊面板，寬度為螢幕寬度的一半（最多 420 dp）。
- 面板位置【決定】：直書放在左側、橫書放在右側，與頁面開始的那一側相反，所以目前這一頁的開頭保持可見（重新排版時就是停在這一頁的第一個字）。
- 點面板外的頁面、按返回鍵或「×」都會關閉面板；面板以外的觸控會交給下方的頁面。
- 面板避開系統列：狀態列、導覽列即使隱藏也預留空間，原因同 1.4 第 2 點。

驗證（`check_settings.py side_panel`，6 項全部通過）：

- 直排書：面板在左側（截圖 `s3-51-side-panel-vertical.png`）；橫排書：面板在右側（`s3-52-side-panel-horizontal.png`）。
- 兩種情況都能從側邊面板改字體，書籍文件的 `font-family` 隨之改變。
- 點面板外的頁面會關閉面板。

另外，7.1 的量測（`font_speed`）4 項全部通過，原始結果在 `screenshots/stage3/check-results-font-speed-side-panel.jsonl`。

驗證時發現並修正：**橫向時工具列的「排版」按鈕被導覽列蓋住，無法點選**（工具列原本只加了上方的系統列內距）。現在左右兩側的系統列與螢幕凹口也會加入內距。這個問題從工具列加入「排版」按鈕時就存在。

腳本方面：橫向時腳本原本用直向畫面的座標點畫面中央，另外在這台沒有硬體加速的模擬器上，偶爾有點擊沒被收到。已改成依實際畫面大小點選，並加上重試。這兩點都是測試腳本的問題，不是 App 的問題。
