## 1. 做了什麼

### 1.1 設定項目 9「雙欄」（設計 5.6 設定表，你回覆「照做」）

| 值 | 行為 |
|---|---|
| 關閉 | 一律單欄 |
| 開啟 | 一律雙欄，直向畫面也是 |
| 僅橫向畫面（預設） | 閱讀畫面寬大於高時雙欄，否則單欄 |

- 放在面板「版面」頁的「翻頁方向」下方（截圖 `s4-01-panel-columns-default.png`）。
- 與其他設定一樣分三層（全部書籍 → 這部作品 → 這個檔案）。全域鍵為 `pref_ebook_columns`，值為 `off`／`on`／`landscape`；不合法的值退回預設（單元測試）。這是新增的鍵，沒有改變任何既有鍵的意義。
- 欄間距固定 40 dp（第 9 題的決定），四邊邊距照設定。兩欄等寬，除不盡的 1 px 併入欄間距。

### 1.2 版面：把第 1 階段的「做法 B」用在直書與橫書

- 雙欄時用兩個 iframe 載入同一份章節檔，兩者都和單欄一樣分頁（直書沿 y 軸、橫書沿 x 軸），只是寬度各為一半。跨頁的第一個 iframe 顯示第 2k 頁，第二個顯示第 2k+1 頁。
- **先讀的一欄在哪一側，跟著「翻頁方向」**：右開 → 第 2k 頁在右欄（直書的預設），左開 → 第 2k 頁在左欄（橫書的預設）。這依照第 5 題的決定（直書右欄先讀、橫書左欄先讀，並可自選左開／右開）。
- 跨頁一律從偶數頁開始。最後一個跨頁只有一頁時，另一個 iframe 隱藏，不會重複顯示前一頁（第 1 階段 4.5 第 3 點的做法）。
- 改設定、旋轉而重新排版時，會回到「包含原本那一頁第一個字」的跨頁（單欄時就是那一頁）。旋轉已驗證（3.3）；雙欄時改設定沒有另外測試，走的是同一段程式【推論】。
- 兩個 iframe 的安全設定與單欄相同：`sandbox="allow-same-origin"`（沒有 `allow-scripts`）、相同的 CSP 與請求過濾；殼層只是多建立一個 iframe，書籍內容沒有多取得任何權限。這是依程式碼的說明；第二個 iframe 沒有另外做「書內腳本不執行、不連網」的測試（第 1、2 階段對單一 iframe 測過）。
- 匯入的字型：兩份文件共用殼層中已載入的同一個字型（階段 3 的 7.1 做法），不會載入兩次。
- 直書時，插圖的最大寬度改用單欄寬度，避免插圖比欄寬（3.2 量到插圖縮成 166 px 寬，完整在頁框內）。

### 1.3 翻頁、頁碼、連結、旋轉

- 下一頁／上一頁一次移動一個跨頁。點擊區、滑動、按鍵的對應沿用既有設定與翻頁方向。
- 頁碼：雙欄時顯示跨頁的兩頁，例如「1/3 · 3–4/23」（第 1 個章節檔，共 3 個；第 3–4 頁，共 23 頁）；最後一個跨頁只有一頁時顯示「23/23」（這一點是依程式，沒有在模擬器上看過）。
- 連結：兩欄都能點；殼層判斷點擊位置落在哪一欄，再找該欄文件中的連結。
- 旋轉：「僅橫向畫面」時，轉成橫向即改為雙欄、轉回直向即改回單欄。
- 旋轉後，等殼層重新排版完成再更新頁碼；打開選單時也會重新讀取一次（見第 4 節第 2 點）。分割畫面改變大小時走同一段程式，但沒有測試。
- 選單顯示時，翻頁鍵交給工具列、不翻頁，這是第 2 階段起的設計，沒有改變。

### 1.4 頁首注音錯位的緩解（設計 4.5 第 6 點）

第 1 階段發現：WebView 69 會把「一頁第一行」的注音畫到前一頁。這次先實驗，再把有效的做法放進殼層。

**實驗**【已查證：模擬器，WebView 69】（`tools/stage4/ruby_experiments.py`，在殼層加入修正之前執行）：直書 EPUB 第一個章節檔、單欄、直向畫面，字級 16、18、20、22、24、26、28、30 各排一次（每次 16 個注音，共 128 個），計算「注音與本字不在同一頁」的個數。判斷方法與第 1 階段相同：用注音與本字的版面位置換算頁碼（第 1 階段曾以截圖確認這種情況在畫面上就是注音畫到前一頁）。

| 加入的 CSS | 錯位（16／18／20／22／24／26／28／30） | 合計 |
|---|---|---|
| 不加（修正前的情況） | 4／0／0／0／2／2／0／6 | 14／128 |
| `rt { line-height: 1 }` | 4／0／0／0／2／2／0／6 | 14／128 |
| 同上＋`ruby { line-height: 2.2 }` | 4／0／0／0／2／0／0／6 | 12／128 |
| 同上＋`ruby { line-height: 2.6 }` | 全部 0 | **0／128** |
| 對照：所有段落行距 2.2 | 2／0／0／0／2／0／2／2 | 8／128 |

**採用的做法**：

- 每次排版完成後檢查：只要有一個注音與本字不在同一頁，就加入 `rt { line-height: 1 } ruby { line-height: 2.6 }` 並重新排版。
- 只有含注音的行會變寬，其他行維持設定的行距。
- 偵測到之後，這次閱讀（直到關閉閱讀畫面）都維持【決定】：錯位是這個 WebView 版本的問題，維持同一套行距可以避免不同章節檔的注音行忽寬忽窄。
- 沒有發生錯位的 WebView（例如第 1 階段測過的桌面 Chromium 153）不會加入這段 CSS，維持書籍原本的樣子。【推論】較新的 Android WebView 若沒有這個問題，也一樣不會加入；這點沒有在實機確認。

### 1.5 我自行決定的細節【決定】

1. **先讀的一欄跟著翻頁方向，而不是書寫方向**：所以「直書＋左開」是左欄先讀，「橫書＋右開」是右欄先讀。這樣翻頁的方向與閱讀的方向一致。
2. **每欄寬度下限 120 dp**：邊距很大或螢幕很窄、每欄會小於 120 dp 時，即使設定為雙欄也改用單欄。
3. **頁碼格式**「3–4/23」。
4. **「僅橫向畫面」看的是閱讀畫面本身的寬高**，不是裝置方向；分割畫面時也照這個規則（分割畫面沒有測試）。
5. **注音的修正偵測到才套用**，套用後這次閱讀都維持（見 1.4）。

### 3.1 方法

- `verify_columns.py`：先把排版設定清回預設，再寫入要測的設定（雙欄、翻頁方向等），從**漫畫閱讀器的入口**冷啟動開書（同時驗證交接）。之後每按一次 Page Down 翻一個跨頁，透過 WebView 除錯介面讀取每個 iframe 中**完全落在頁框內**的每個非空白字元（`probe2.js`），直到全書最後一個跨頁。
- `summarize2.py`：每個章節檔，把各跨頁「第一欄＋第二欄」的可見字依序串起來，必須**恰好等於**該檔全部有排版的字（不缺、不重複、不亂序、沒有只露出一部分的字）；每個跨頁都要看過；【第１段】到【第１２０段】要依序出現；第一欄要在預期的一側。注音（`rt`、`rp`）不列入，另外檢查（3.6）。
- 翻頁用 Page Down 鍵而不是點擊，因為點擊可能剛好落在連結上；點擊與連結另外檢查（3.4）。

## 4. 過程中發現並修正的問題

App：

1. **排版進行中旋轉，排版會停在旋轉前的尺寸**（第 2 階段就存在，讀程式碼時發現）：殼層在排版完成前不接受新的重新排版，所以排版途中收到的尺寸變化被丟掉，排版完成後仍是舊的寬高。
   - 舊版重現【已查證：模擬器】：在直向開始一次重新排版，排版途中轉成橫向（頁面記錄顯示：重新排版開始時視窗為 412×732，尺寸變化事件 732×412 到達時排版仍在進行）。排版完成後畫面是橫向，兩欄卻仍是直向時的寬度（各 182 px，擠在左側 400 px 內），文字超出畫面下緣，右半邊空白，之後也沒有再重新排版（截圖 `s4-40-old-busy-rotation.png`）。

## 5. 沒有驗證或還沒做的部分

- **實機**：全部只在 Android 8.0 模擬器（WebView 69）驗證；較新的 Android／WebView、實機的效能與手感都沒有驗證。
- **做法 A 沒有實作**：設計 5.3 原本是「WebView 支援 `column-wrap` 時用做法 A（只排版一次），否則用做法 B」。這次只做了 B，原因：
  - B 在不支援 `column-wrap` 的 WebView 69 上正確（第 1 階段與本階段都驗證過）。原型中，A 在支援的瀏覽器上與 B 的分欄結果完全相同。
  - 這個環境沒有支援 `column-wrap` 的 Android WebView，A 在 Android 上無法驗證。
  - A 的好處是效能：只排版一次、記憶體中只有一份文件。

  這與設計不同，需要你決定是否補做（第 6 節）。
- **雙欄的成本**：雙欄時同一份章節檔會載入並排版兩次，記憶體中也有兩份。在模擬器上，開一個章節檔約為單欄的 2–5 倍時間（3.8）；記憶體用量沒有量測；實機都沒有量測。
- **注音的修正**：只用測試書的寫法驗證（`<ruby>漢<rt>ㄏㄢˋ</rt></ruby>`）。使用 `<rb>`、`<rtc>` 或其他寫法的書沒有測試。修正生效時，含注音的行會比其他行寬。
- **模擬器上當機 1 次**（3.8）：繪圖層建立視窗表面失敗（`EGL_BAD_ALLOC`），與第 3 階段那一次相同，原因沒有查明，實機上是否會發生未驗證。
- **沒有在模擬器上實測的細節**（依程式推論）：雙欄時改設定後回到同一個字、最後一個跨頁只有一頁時的頁碼「23/23」、分割畫面、第二個 iframe 的「書內腳本不執行、不連網」。
- **Release 版**：這個階段沒有在模擬器上操作 release 版，只確認能建置（第 2 節）。
- **其他階段的項目**：閱讀位置與已讀紀錄、目錄與進度滑桿（階段 5），翻頁動畫（含雙欄以中線翻頁）都還沒做。
