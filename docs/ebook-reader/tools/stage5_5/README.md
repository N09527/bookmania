# 階段 5.5 的驗證腳本（翻頁動畫、文字閱讀器章節面板）

這些腳本只用於測試，不屬於 App。

需求與 `../stage5/README.md` 相同（`adb`、Python 3、已安裝 debug APK 並放好測試書的模擬器、App 語言為繁體中文、螢幕 1080×1920），另外需要本機的 `ffmpeg`、`ffprobe`、Pillow 與 numpy。`check_pageturn.py` 會用到 `../stage5/check_stage5.py`（以及它用到的 `../stage3/drive.py`、`../stage4/verify_columns.py`）。

| 檔案 | 用途 |
|---|---|
| `check_pageturn.py` | 模擬器上的各項檢查，結果逐行寫入 `out/results.jsonl`；每次翻頁的錄影、逐格畫面與分析在 `out/rec/<名稱>/`，挑出的畫面並排成 `out/shots/<名稱>-frames.png`。步驟見檔案開頭的說明 |
| `run-all.sh` | 依序執行本階段的全部檢查。`./run-all.sh 7` 從第 7 項開始；`STEPS="3 5 7-9" ./run-all.sh` 只跑指定的項目 |
| `summarize.py` | 依 `out/results.jsonl` 列出每次執行，以及每個檢查最後一次的結果 |
| `timings.py` | 依 `out/results.jsonl` 中 App 的 debug 紀錄，列出每次翻頁的準備時間、開始播放的時間與每秒格數 |
| `make_varied_epub.py` | 產生內容不重複的測試 EPUB（`python3 -I make_varied_epub.py zh-varied.epub`）。原有的橫排測試書段落文字相同、只有段落編號不同，橫向雙欄時前後跨頁的畫面幾乎一樣，逐格分析分辨不出來 |

做法：

- 每次翻頁用模擬器的 `screenrecord` 錄下，按鍵（Page Down／Page Up）在錄影開始後送出。翻頁前、翻頁後各截一張圖。
  - 錄影期間把系統的「動畫時間比例」設為 40（動畫慢 40 倍），錄完改回 1。這部模擬器沒有硬體加速，即使放慢，每秒也只畫出約一格動畫。
  - 文字書的錄影縮為畫面的一半；漫畫頁只靠顏色就能分辨，縮為四分之一以減少編碼負擔。
  - 在這部模擬器上，`input keyevent` 從下指令到 App 收到按鍵要好幾秒，所以每次錄 60 秒。
- App（debug 版）在每次播放動畫時寫入 logcat：準備（複製畫面、顯示疊層）花了多久、換頁後多久開始播放、畫了幾格；沒有播放時也寫明原因。檢查讀這些紀錄確認動畫有沒有播放（長條模式與關閉捲曲時應該沒有）。
- 逐格分析：畫面切成格子（半尺寸錄影 20×20 像素、四分之一尺寸 10×10），只看「翻頁前後兩頁內容不同」的格子，比較時取紅綠藍三個色版中差最多的一個。每一格判定為「舊頁」（與翻頁前相同）、「新頁」（與翻頁後相同）或兩者皆非（捲起的頁背、陰影、移動中的頁）。錄影壓縮會讓畫面與截圖略有出入，所以「舊頁／新頁的比例」以這次錄影中最高的比例為基準。
  - 有動畫：至少一格畫面既不是翻頁前、也不是翻頁後的樣子（兩種比例都低於最高值的八成）。「無」則不應有這種畫面。
  - 捲曲的方向：動畫中第一格出現新頁的畫面，新頁在哪一半（往後翻：左開先出現在右半、右開在左半；往前翻相反；直向翻頁模式往後翻先出現在下半）。
  - 雙欄（雙頁）以中線翻一頁：翻頁前半段，新頁只出現在被翻起的那一半；另一半是捲起的頁背（帶著新頁的內容，但位置與角度還不是最後的樣子）。
  - 滑動：從翻頁前、後兩頁各取有文字的小區塊，在畫面的同一列找它們的位置，求出舊頁與新頁各移動了多少（多個區塊結果一致才採用）。舊頁應往翻頁方向移出、新頁從另一側進來。
  - 翻頁後畫面不再變化（沒有留下疊層）。
  - 錄到的格數受模擬器速度影響，比實機少得多；判定不依賴格數。
- 章節面板：在作品「橫排測試書 EPUB」的資料夾放入兩個檔案（`add_chapter`）：內容不重複的 EPUB，以及一個圖片章節（複製測試用的 CBZ）；在作品頁下拉重新整理（沒有生效時重試，最多 3 次）。之後檢查面板列出的章節、長按切換已讀、書籤按鈕、點選文字章節與圖片章節分別開在哪個閱讀器，以及離開的章節有沒有存下位置。這個作品因此多了兩個章節（第 6 階段回歸時要注意）。
- 設定：文字閱讀器排版面板「版面」分頁的「翻頁動畫」，以及設定 > 閱讀的「捲曲翻頁」開關。
- 第 6 階段加入的項目（第 30～36 項，使用者在第 5.5 階段報告 6.1 的決定）：
  - `t-default`：沒有存過翻頁動畫設定時，文字閱讀器以捲曲翻頁；設定檢查（第 27 項）也改為預期「捲曲」是預設選項。
  - `--swipe`：以 `input swipe` 代替按鍵。開啟捲曲時用 400 毫秒的快速滑動，檢查頁面不跟著手指、放開後以捲曲翻頁（左開、往前翻、右開、直向）。
    - 太短的滑動在這部模擬器上只送出按下、起點的一次移動與放開，中間沒有移動，所以用 400 毫秒。
    - 頁面不跟著手指：錄影中新頁出現之前的每一格，量漫畫測試頁黑框的位置（`frame_shift`）。開啟捲曲時黑框應該不動；捲曲關閉時應該跟著手指移動。
    - 這項檢查是在第一次執行之後才加入的，所以第一次執行的錄影用 `swipe_frames` 補做。
  - 捲曲關閉（`i-swipe-off-drag`）：翻頁器自己跟著手指移動，放開時依它原本的規則決定是否翻頁（夠快，或拖過頁寬約六成）。
    - 第一次執行用同樣的 400 毫秒快速滑動（`i-swipe-off`），頁面跟著手指移動約一半後彈回，沒有翻頁。
    - 用 `dumpsys input` 看到 App 收到的移動事件間隔 20～130 毫秒，最後兩次移動相隔 126 毫秒。`input` 會等 App 處理完一個事件才送下一個。
    - 【推論】Android 8 只用最近 100 毫秒內的移動估計速度（放開那一下不算），所以翻頁器量到的速度是 0，只能依拖動的距離判斷。
    - 因此這一項改為慢慢拖過大半頁（1.5 秒，從頁寬 93% 拖到 7%）。
  - 長條模式（`i-swipe-webtoon-up`）：手指往上滑，檢查長條跟著捲動、App 沒有播放捲曲。
    - 長條的「目前頁」是底邊在畫面內的最後一頁；這裡的頁面幾乎和畫面一樣高，一次滑動到不了下一頁，所以不檢查頁碼。
    - 改為比較翻頁前後的截圖，找出畫面往上移動多少（`scroll_shift`）。
    - 第一次執行（`i-swipe-webtoon`）誤用左右滑動，長條不會左右捲動，所以「頁面有翻」不通過。這是腳本的錯誤。
